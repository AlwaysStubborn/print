# 岛上采果 · 小白视角评测（设计期）

## 范围

- 假装自己是**第一次玩、不懂股票**的人
- **不要**往游戏里加评测功能
- **不要**要求游戏终局解释「这是在比喻投资」——课要靠玩出来，不靠揭穿

## 人物设定（评测时代入）

- 没炒过或只跟过热门
- 听过「别人赚很多」容易心动
- 怕猜、也怕踏空

## 必玩路径

1. 种子固定（自己填一个并记下），策略选 **混合规矩**，玩完
2. **同一天气**，策略改 **跟岛民**，再玩完
3. （可选）同一天气再跑 **全程坚果**

玩的时候少看设计文档，多看会不会懵。

## 玩完先口述（不给选项）

自己用一句话回答：

1. 这游戏在练什么？
2. 为什么规矩对了还可能少果子？
3. 岛民传言像生活里什么事？
4. 跟风赢了一局，会不会觉得跟风才对？

## 通过标准

| 项 | 算通过 |
|----|--------|
| 能感到「天气管不住」 | 是 |
| 能感到「规矩有用但不保证好看」 | 是 |
| 能感到「听传言会乱」 | 是 |
| 总结成「要会猜晴雨」 | **不通过** |
| 总结成「要听岛民」 | **不通过** |
| 只想赌一把翻本 | **不通过** |

## 对照你的真实经验（评测员心里用，别写进游戏）

- 买完就跌 → 看「刚采完就下雨」够不够疼、够不够清楚
- 别人赚钱想跟 → 看传言会不会把人带跑
- 一局定好坏 → 看「同一天气换采法」引没引导到

## 输出格式

```
小白视角：通过 / 勉强 / 不通过
玩家可能悟到的：
玩家可能悟歪的：
最容易懵的一步：
建议改文案/节奏：（仍不要揭隐喻）
```

## 改代码规则

默认只出报告。用户说「按评测改」才改游戏；改时仍**不要**加隐喻揭晓。
