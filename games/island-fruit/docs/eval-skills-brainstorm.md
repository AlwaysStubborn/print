# 「岛上采果」评测 Skills 头脑风暴

> 状态：讨论稿（先对齐，再写成正式 skill）  
> 对象：`games/island-fruit/` 网页小游戏  
> 目标：用三种角色视角评测并反哺设计；技能本身可复用于后续改版

---

## 0. 为什么要做评测 skills

游戏要传达的不是「如何炒股」，而是：

1. **随机不可控**
2. **选择有后果，但选对 ≠ 结果好**
3. **过程分与结果分可以背离**
4. **跟风故事会劫持决策**

若只靠开发者自测，容易陷入：
- UI 自嗨（自己觉得清楚）
- 隐喻过重（小白看不懂在玩什么）
- 产品目标漂移（做成赌运气小游戏）

因此需要 **固定角色的评测协议**：每次改版用同一套问题打分，可对比。

## 1. 三个评测角色（Skills 候选）

| Skill 代号 | 角色 | 核心问题 | 成功标准 |
|------------|------|----------|----------|
| `eval-game-ux` | UI / 交互人员 | 能不能 30 秒懂规则、少挫败地走完一局？ | 认知负荷低、反馈及时、无死胡同 |
| `eval-game-novice` | 炒股小白（隐喻读者） | 玩完能否感到「不可控 + 规矩有用」？ | 不依赖金融词也能悟到课 |
| `eval-game-pm` | 产品经理 | 这款游戏的「工作」是什么？有没有做成赌场？ | JTBD 清晰、反模式自检通过 |

可选第四角色（暂缓）：
- `eval-game-educator`：行为金融/教学设计者（对照经典实验）

## 2. 经典案例库（用来补规则，不是抄玩法）

### 2.1 交互 / 游戏 UX

| 案例 | 启示 | 迁到本游戏 |
|------|------|------------|
| **Nintendo 初见 30 秒法则** | 不看说明书也能开始 | 开始页文案是否过长？首回合是否要强制点「下一步」说明？ |
| **Don Norman：反馈与映射** | 动作→可见结果 | 采摘后地块高亮 + 背包数字变化是否够醒目？ |
| **Hick's Law** | 选项越多决策越慢 | 传言出现时「听 / 不听」是否足够二元？忌再加第三灰色选项 |
| **Progressive disclosure** | 先核心后细节 | 概率表、设计隐喻说明放到终局/帮助，不堆开始页 |
| **Dark Pattern：确认羞辱** | 反面教材 | 拒绝「只有笨蛋才听传言」这类文案 |
| **《塞尔达》教程隐式教学** | 做中学 | 「刚采完就下雨」用事件教，少用说明书教 |

### 2.2 炒股小白 / 行为金融（隐喻层）

| 案例 | 启示 | 迁到本游戏 |
|------|------|------------|
| **前景理论（Kahneman）** | 亏的痛感 > 赚的快感 | 暴雨扣分的情绪冲击是否压过晴天喜悦？过程分要托住「守规矩」 |
| **处置效应** | 爱卖赚的、死拿亏的 | 是否诱导玩家在暴雨后「清仓」？应让清仓变难（延迟生效）——已有雏形 |
| **FOMO / 社会证明** | 别人赚钱→跟买 | 岛民传言 = 雪球/同事叙事；跟风策略应有「假胜利」 |
| **蒙提霍尔** | 直觉概率常错 | 终局强调「同种子多开」，单局不能证明策略 |
| **同事年化 12% 后回撤一半** | 收益叙事 vs 波动体验 | 跟风局允许高结果分 + 低过程分 |
| **买完就跌** | 正确买入仍难受 | 「刚采完就下雨」必须保留且可感知 |

### 2.3 产品 / 机制设计

| 案例 | 启示 | 迁到本游戏 |
|------|------|------------|
| **Jobs to be Done** | 用户雇产品完成什么工作 | JTBD：在安全环境里体验「不可控下的规矩」 |
| **赌场 RTP / 近赢** | 反面：用概率成瘾 | **禁止**近赢特效、连抽、充值；随机服务教学不是沉浸赌博 |
| **Duolingo 习惯环** | 轻量重复 | 「同一天气换策略」比排行榜更符合教学目标 |
| **Oregon Trail** | 随机死亡 + 决策 | 随机可残酷，但要可复盘（日志/种子） |
| **《平衡球》类物理玩具** | 机制即隐喻 | 三地块气质要一眼可感，勿依赖长文 |
| **双分数板（游戏化学习）** | 拆开「得分」与「做得对」 | 结果分 / 过程分是产品核心，不可合并 |

## 3. 各 Skill 评测维度草案

### 3.1 `eval-game-ux`（UI 交互）

**评分 1–5，加权建议：**

| 维度 | 权重 | 检查问题 |
|------|------|----------|
| 首屏理解 | 20% | 未读完长文能否选出策略并开始？ |
| 回合反馈 | 25% | 天气、选地、产量变化是否 1 秒内可读？ |
| 移动端 | 15% | 小屏是否可点、日志是否可滚？ |
| 错误预防 | 15% | 传言态下是否禁用「下一步」防误触？ |
| 心流节奏 | 15% | 12 回合是否过长/过短？传言是否打断过频？ |
| 视觉气质 | 10% | 是否避免通用 AI 紫白风？信息层级是否清晰？ |

**必现缺陷清单（出现即记 FAIL）：**
- [ ] 关键按钮无反馈
- [ ] 终局无法回到同种子重开
- [ ] 颜色对比度过低无法读数
- [ ] 只有结果分、过程分不可见

**输出格式：**
```
UX 总分 / 分级（可上线微调 / 需改版 / 阻断）
Top 3 问题（带截图或步骤）
Quick wins（<1h）
```

### 3.2 `eval-game-novice`（炒股小白）

**设定人物：**
- 没炒过股或只跟过热门
- 听过「同事赚了 12%」
- 害怕预测、容易被话术带跑

**通关后口述测试（不给选项先问）：**
1. 这游戏在练什么？
2. 为什么有时候规矩对了还是会少果子？
3. 岛民传言像生活中什么？
4. 你会不会因为一局跟风赢了就觉得跟风好？

**评分维度：**

| 维度 | 通过标准 |
|------|----------|
| 隐喻可达 | 不提股票也能说出「随机 / 规矩 / 跟风危险」 |
| 情绪真实 | 能联想到「买完就跌」类体验 |
| 无有害迁移 | 不会总结成「要猜天气」或「要听岛民」 |
| 动机健康 | 想再开是为了对比策略，不是为了赌一把翻本 |

**经典案例对照题（评测员自用）：**
- 若玩家终局说「下次我要猜暴雨」→ **教学失败**（变成预测游戏）
- 若玩家说「混合规矩这局亏了所以规矩没用」→ **需加强多局/同种子对比引导**

### 3.3 `eval-game-pm`（产品经理）

**北极星（候选，讨论）：**
- A. 「同种子换策略完成率」
- B. 「过程分 ≥90 且理解选对≠结果好的自述率」
- C. 「7 日内自愿重开 ≥3 局且策略有切换」

建议北极星：**B**（学习目标），A/C 为过程指标。

**反模式审计（赌场化检查）：**

| 反模式 | 本游戏是否触碰 | 处置 |
|--------|----------------|------|
| 近赢动画诱导再来一局 | ? | 禁止强化 |
| 排行榜攀比 | 无 | 保持无 |
| 付费重置/开箱 | 无 | 保持无 |
| 单局定胜负叙事 | 有风险 | 终局强制提示多开 |
| 惩罚「不玩」 | 无 | 保持无 |

**价值主张一句话（草案）：**
> 用 5 分钟安全地体验：随机世界里，规矩保护的是下限，不是每一局的面子。

**范围边界：**
- In：机制调参、文案、同种子对比、教学事件
- Out：真实行情接入、社交分享排行、复杂养成

## 4. Skill 工作流（三个角色共用骨架）

```
1. 启动条件：改版 island-fruit 后 / 用户要求评测
2. 读取：index.html + game.js + 本讨论结论
3. 按角色清单走 1～2 局（规定策略）
4. 对照经典案例表打勾
5. 输出：分数 + 缺陷 + 改版建议（分 P0/P1/P2）
6. 不直接改代码，除非用户要求「按评测结果改」
```

**强制游玩路径（保证可比）：**
1. 种子固定例如 `tide-2026` + 混合规矩
2. 同种子 + 跟岛民
3. （可选）同种子 + 全程坚果

## 5. 争议点（需要你拍板）

### 5.1 隐喻要不要在终局揭晓？
- **揭晓**：利于「啊原来是投资」迁移  
- **不揭晓**：更纯，避免变成说教  
- **建议**：默认不揭；帮助页折叠「设计意图」

### 5.2 过程分是否向玩家解释算法？
- 全透明 → 可能被「刷过程分」  
- 全黑箱 → 小白不懂为何扣分  
- **建议**：原则透明（听传言会扣），公式不公开

### 5.3 第一版 skills 放哪？
- A. 仓库 `games/island-fruit/skills/`（跟游戏走）  
- B. 用户级 `~/.cursor/skills/`（可复用到别的教学游戏）  
- **建议**：先放仓库游戏目录，验证后再提炼通用版

### 5.4 是否要第四角色「行为金融教练」？
- 利：案例更深  
- 弊：与小白角色重叠  
- **建议**：v1 不做，把案例表并进小白 + PM
